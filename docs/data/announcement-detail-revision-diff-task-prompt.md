# 공고 상세 이력 비교 기능 작업 지시

현재 구현된 `announcement_detail_revisions`의 `before_json`과 `after_json`을 비교해, 관리자가 어떤 값이 바뀌었는지 즉시 확인할 수 있는 기능을 구현한다.

## 목표

- 이력 목록에서 특정 확정·복원 작업의 변경 항목 수를 확인한다.
- `변경 내용 보기`를 누르면 이전값과 이후값을 나란히 표시한다.
- 보증금·월세·전용면적·주소·공급호수·기관·호실·일정·신청조건의 추가·수정·삭제를 사람이 읽을 수 있는 한글 라벨로 표시한다.
- 원본 스냅샷을 브라우저에서 임의로 비교하지 않고 서버가 비교 결과를 만들어 반환한다.

## 범위와 제약

- 새 라이브러리를 추가하지 않는다.
- 기존 `announcement_detail_revisions` 스냅샷을 재사용하고, 운영 상세 데이터는 변경하지 않는다.
- 비교 기준은 `sourceSiteKey`, `sourceUnitKey`, `optionKey`를 우선 사용한다. 키가 없으면 배열 순서를 보조 기준으로 쓴다.
- `null`, 빈 문자열, 누락값은 화면에서 `없음`으로 일관되게 표시한다.
- 값 전체를 JSON으로 노출하지 않는다.
- 변경이 없는 이력도 오류가 아니라 `변경된 항목이 없습니다.`로 표시한다.

## API 설계

`GET /api/admin/announcements/{announcementId}/detail-revisions/{revisionId}/diff`

응답:

```json
{
  "revisionId": "...",
  "action": "PDF_COMMITTED",
  "createdAt": "...",
  "changes": [
    {
      "section": "임대 조건",
      "label": "세이지움 개봉 · 36.65㎡ · 기본 조건 · 보증금",
      "before": "151,000,000원",
      "after": "155,000,000원",
      "kind": "CHANGED"
    }
  ]
}
```

`kind`는 `ADDED`, `REMOVED`, `CHANGED`만 사용한다. 목록은 섹션과 라벨 기준으로 안정적으로 정렬한다.

## 비교 규칙

| 대상 | 한글 섹션 | 비교 항목 |
| --- | --- | --- |
| 단지 | 공급 주택 | 단지명, 주소, 공급호수, 기관 역할 |
| 주택형 | 공급 주택 | 공급유형, 주택형, 전용면적, 공급호수, 호실 |
| 임대조건 | 임대 조건 | 조건 설명, 보증금, 월세 |
| 일정 | 일정 | 시작, 종료, 상태, 설명 |
| 신청조건 | 신청 조건 | 대상, 순위, 가구원 수, 연산자, 기준값, 단위, 설명 |

금액은 `#,###원`, 면적은 `㎡`로 포맷한다. 추가·삭제는 반대쪽 값을 `없음`으로 표시한다.

## 화면 설계

- 각 이력 행에 `변경 내용 보기` 버튼을 추가한다.
- 선택한 이력 바로 아래에 비교 패널을 연다. 다른 이력을 선택하면 기존 패널은 닫는다.
- 패널에는 `변경 n건`과 섹션별 그룹을 보여 준다.
- 각 변경 행은 `항목명 | 이전 값 | 이후 값` 세 열 구조로 구성한다.
- 추가는 이후 값만, 삭제는 이전 값만 시각적으로 강조한다.
- 복원 버튼은 기존 위치와 동작을 유지한다.
- 모바일에서는 변경 행을 한 열로 전환하고 `이전`, `이후` 라벨을 표시한다.
- 로딩·오류·빈 변경 상태는 `aria-live`로 안내한다.

## 테스트와 완료 기준

1. 보증금 변경이 `임대 조건`의 이전·이후 금액으로 반환된다.
2. 일정 추가와 신청조건 삭제가 각각 `ADDED`, `REMOVED`로 반환된다.
3. 다른 공고의 이력 ID는 조회할 수 없다.
4. 이력이 없거나 값이 같은 경우 빈 변경 배열을 안전하게 반환한다.
5. 관리자 HTML·JS·CSS에 비교 패널과 API 연결이 존재한다.
6. 기존 PDF 확정·복원·롤백 테스트가 모두 통과한다.
