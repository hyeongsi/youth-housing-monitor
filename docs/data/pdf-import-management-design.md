# PDF 분석 관리 화면 설계

> 구현 상태: 기존 정적 화면 기준 설계. PDF 목록·상태·업무 규칙은 유지하되, React 전환 이후 화면 파일·컴포넌트·경로 기준은 [React 프론트엔드 전환 아키텍처](../ui/react-frontend-architecture.md)를 우선한다.

## 목적

이미 업로드·분석된 PDF 초안을 한 화면에서 찾아 상태와 검토 필요 항목을 확인하고, 기존 검토 화면으로 다시 진입한다.

## 화면

- 경로: `/admin-imports.html`
- 상단 상태 필터: 전체, 검토 초안(`DRAFT`), 저장 준비(`READY`), 확정됨(`COMMITTED`), 분석 실패(`FAILED`)
- 검색: 공고명·기관·문서 유형
- 목록 열: 공고명, 기관, 문서 유형, 분석 상태, 검토 필요 근거 수, 파서 버전, 업로드 시각
- 행의 `검토 열기`는 `/admin-import.html?id={id}`로 이동한다.
- 실패 행에는 오류·경고 요약을 표시한다.

## API

- `GET /api/admin/document-imports?status=&query=&page=&size=`
- DB의 `document_extractions`를 `announcements`와 조인한다.
- 응답은 목록 전용 최소 데이터와 `totalCount`, `hasNext`를 반환한다.
- 기존 단건 조회·업로드·확정 API는 변경하지 않는다.

## 접근·상태 원칙

- 모든 PDF 초안은 관리자 관리 목록에 남는다. 확정본도 이력 확인을 위해 표시한다.
- 사용자용 공고 API에는 PDF 초안·근거·오류 정보를 노출하지 않는다.
- 목록은 삭제 기능을 제공하지 않는다. 삭제·복원 이력 정책은 별도 작업으로 분리한다.

## 완료 기준

- 상태별 필터, 키워드 검색, 페이지 이동
- 검토 필요 개수와 실패/경고 표시
- 기존 검토 화면 재진입
- 360px와 데스크톱에서 목록이 읽히고, 키보드 포커스가 보임
