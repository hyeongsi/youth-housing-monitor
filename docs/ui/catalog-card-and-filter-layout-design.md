# 공고 카드·검색 조건 정렬 개선 설계

> 상태: 구현 완료  
> 대상: `web/src/App.tsx`, `web/src/features/announcements/AnnouncementFilterForm.tsx`, `web/src/app.css`, `web/src/components/ui.module.css`

## 1. 문제와 원인

| 화면 | 현재 문제 | 원인 |
| --- | --- | --- |
| 공고 카드 | 행동 버튼이 두 줄로 나뉘고 카드마다 하단 높이가 달라진다. | 모든 행동을 같은 폭으로 나누는 `.actions > * { flex: 1 }` 규칙과 긴 버튼명이 함께 적용된다. |
| 검색 조건 | 단위 안내가 있는 입력칸과 없는 입력칸의 높이가 달라 보인다. | 필드, 체크 조건, 실행 버튼이 하나의 3열 Grid의 직접 자식으로 섞여 있다. |
| 체크 조건 | 체크박스와 문구가 줄바꿈되며 시작선이 맞지 않는다. | 체크 조건 레이블의 높이·정렬·열 규칙이 없다. |

글자를 작게 줄이거나 모든 버튼의 높이를 키우는 방식은 사용성을 악화시키므로 적용하지 않는다.

## 2. 공고 카드 행동 영역

### 2.1 행동 우선순위

1. 주요 행동: `공고문 보기` — 파란 채움 버튼
2. 보조 행동: `상세 보기` — 테두리 버튼
3. 상태·선택 행동: `관심 저장`, `비교` — 가벼운 텍스트 버튼

화면 표기는 아래처럼 짧게 유지한다.

| 현재 | 변경 표기 | 접근성 이름 |
| --- | --- | --- |
| 관심 저장 / 관심 저장 해제 | 관심 저장 / 저장됨 | 현재 동작을 포함한 `aria-pressed`와 `aria-label` |
| 비교에 담기 / 비교에서 빼기 | 비교 / 비교됨 | 현재 선택 상태를 포함한 `aria-pressed` |
| 상세 보기 | 상세 보기 | 공고명을 포함한 `aria-label` |
| 공식 공고문 보기 | 공고문 보기 | `공식 공고문 보기 (새 탭에서 열림)` |

### 2.2 구조

`AnnouncementCard`의 행동 영역은 다음 두 그룹으로 나눈다.

```text
[관심 저장] [비교]                 [상세 보기] [공고문 보기]
```

- 왼쪽 상태·선택 그룹은 콘텐츠 폭만 사용한다.
- 오른쪽 주요·보조 그룹은 고정 최소 폭을 사용한다.
- 카드 행동 버튼은 줄바꿈하지 않는다. `white-space: nowrap`, `word-break: keep-all`을 적용한다.
- `.actions > * { flex: 1 }` 공통 규칙은 제거하고, 카드 전용 `.cardActions`, `.cardUtilityActions`, `.cardPrimaryActions`로 한정한다.
- 420px 이하에서는 상태·선택 그룹을 첫 줄 전체 폭에 두고, `상세 보기`·`공고문 보기`를 둘째 줄 2열로 배치한다. 주요 행동이 잘리거나 두 줄이 되지 않게 한다.

아이콘 전용 버튼이나 새 라이브러리는 도입하지 않는다. 이후 카드 폭이 더 좁아지거나 행동이 추가될 때만 `더보기` 메뉴를 검토한다.

## 3. 검색 조건 폼

### 3.1 영역 분리

검색 폼을 하나의 Grid가 아니라 아래 3개 영역으로 분리한다.

```text
검색 기준
  [통합 검색] [시·도] [시·군·구]
  [읍·면·동] [출처] [주택 유형]
  [모집 상태] [보증금 상한] [월세 상한]
  [전용면적 최소] [전용면적 최대] [정렬]

추가 조건
  [☐ 마감 공고 포함] [☑ 정보 미확인 공고 포함] [☐ 마감 임박 공고만]
  [☐ 내 관심 조건 일치] [☐ 관심 저장만] [☐ 추가모집만 보기]

                                                    [초기화] [검색]
```

- 입력 영역: `filterFieldGrid`, 데스크톱 3열 / 태블릿 2열 / 모바일 1열
- 추가 조건: `fieldset`과 `legend`를 사용한 `filterOptionGroup`
- 실행 영역: `filterFooter`, 데스크톱 오른쪽 정렬 / 모바일 2열 전체 폭
- `확인 시점 지난 공고만`은 `관심 저장만`이 선택되었을 때 추가 조건 Grid의 마지막 항목으로 표시한다.

### 3.2 필드 높이와 단위

- 라벨, 입력칸, 보조 안내의 순서를 모든 필드에서 동일하게 유지한다.
- 원·㎡는 입력칸 안의 접미사로 이미 표시되므로 `원 단위`, `㎡ 단위` 도움말은 제거한다.
- 오류 메시지가 없는 필드는 도움말 영역을 비워 높이를 맞추지 않는다. 각 행의 Grid 정렬로 시작선만 맞춘다.
- 금액·면적 필드는 기존 44px 높이, 쉼표 표시, API 숫자값 분리 규칙을 유지한다.

### 3.3 체크 조건 규칙

- 각 체크 레이블은 `display: flex`, `align-items: center`, `gap: 8px`, `min-height: 44px`를 사용한다.
- 체크박스는 고정 폭이며 레이블 문구는 기본적으로 한 줄을 유지한다.
- 데스크톱은 3열, 760px 이하는 2열, 480px 이하는 1열이다.
- 체크 조건은 배지·카드처럼 과도하게 꾸미지 않고, 연한 보조 표면과 얇은 경계선으로 입력 영역과만 구분한다.

## 4. 공통 버튼 규칙

- 기본 버튼은 최소 44px 높이를 유지한다.
- 카드와 검색 조건에서만 필요한 폭·정렬은 화면 전용 클래스에서 관리한다. 모든 공통 버튼에 고정 폭이나 말줄임 규칙을 추가하지 않는다.
- 파란 버튼은 같은 행동 그룹에서 하나만 사용한다.
- 버튼 레이블은 행동을 설명하는 2~5글자 중심으로 작성하고, 긴 설명은 `aria-label`, 보조 문구, 툴팁으로 제공한다.
- 비활성·로딩·키보드 포커스 규칙은 기존 `Button` 컴포넌트를 그대로 사용한다.

## 5. 구현 순서

1. `AnnouncementCard` 행동 마크업을 상태·주요 행동 그룹으로 분리하고 짧은 표기·접근성 이름을 적용한다.
2. 공고 카드 전용 행동 CSS와 420px 이하 규칙을 추가한다.
3. `AnnouncementFilterForm`을 입력 Grid, `fieldset` 체크 조건, 실행 Footer 구조로 나눈다.
4. 검색 조건 CSS를 3/2/1열 반응형 규칙으로 적용하고 단위 도움말을 정리한다.
5. 데스크톱 1180px, 태블릿 768px, 모바일 360px에서 카드·검색 조건·키보드 포커스를 검증한다.

## 6. 완료 기준

- 공고 카드의 행동 버튼이 2줄로 쪼개지지 않는다.
- 카드별 행동 영역 높이가 같고, 공고명·메타 영역과 겹치지 않는다.
- 검색 입력 12개가 행·열 기준으로 정렬되고, 체크 조건과 실행 버튼이 입력 Grid를 밀어내지 않는다.
- 체크박스 문구와 체크 상자가 수직 중앙에 맞으며 좁은 화면에서는 안전하게 열 수가 줄어든다.
- 360px에서 버튼·입력값·단위·레이블이 겹치거나 잘리지 않는다.
