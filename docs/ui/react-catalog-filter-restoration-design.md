# React 공고 검색 필터 복구 설계

## 범위

React `AnnouncementSearchPage`는 기존 Spring `GET /api/announcements` 계약을 변경하지 않고 아래 조건을 복구한다.

- `areaMin`, `areaMax`, `source`, `includeClosed`, `includeUnknown`
- `interestOnly`와 저장 관심 조건(`interestRegion`, 금액·면적·정보 미확인 포함)
- `savedOnly`와 반복 `savedId`
- `supplementalOnly`, `sort` (`LATEST`, `DEADLINE`)

## 상태 규칙

- 입력값은 `draft`에만 반영한다.
- `검색` 클릭 시 비어 있지 않은 값을 URL Search Params에 반영한다.
- 지역은 `시·도 → 시·군·구 → 읍·면·동`의 3단계 선택으로 제공하며, 상위 지역이 바뀌면 하위 선택값을 비운다. 검색 시 가장 상세한 선택값만 `region`으로 변환한다.
- URL에는 지역 단계 선택값과 최종 `region`을 함께 유지해 새로고침·뒤로 가기에도 UI를 복원한다. API 요청에서는 지역 단계 선택값을 제외하고 최종 `region`만 전달한다.
- URL 값만 `applied`로 API에 전달하며, 적용·초기화 시 페이지는 1로 돌아간다.
- `공고 더 보기`는 같은 applied 조건으로 다음 페이지를 요청한다.
- `savedId`는 localStorage의 관심 저장 ID 목록에서 만들어 URL에 노출하지 않는다.
- 관심 조건의 단일 원본은 `GET/PUT /api/profile`이다. `preferredAreas`, `maxDeposit`, `maxMonthlyRent`, `minExclusiveArea`, `maxExclusiveArea`를 저장하고, 공고 검색은 overview의 `profile`을 관심 조건 파라미터로 변환한다.
- 카드의 `관심 저장`은 브라우저별 저장 목록으로 관리하며, `관심 저장만` 검색 시에만 반복 `savedId` 파라미터로 전달한다.
- 검색 결과 위에는 URL에 적용된 조건만 칩으로 표시한다. 각 칩은 해당 조건만 해제하며, `전체 해제`는 URL·입력값·페이지·누적 결과를 함께 초기화한다.
- 보증금·월세 입력은 3자리 쉼표를 표시하지만 URL·API에는 숫자만 보낸다. 전용면적은 소수 입력을 유지하고 입력칸에 `㎡` 단위를 표시한다.
- 카드의 조건 일치 표시는 목록 응답의 상세 위치·주택형·임대조건에서 실제로 검증된 지역·면적·임대조건만 사용한다. 값이 없거나 정보 미확인 허용으로 포함된 공고에는 일치 이유를 추정해 표시하지 않는다.
- 결과가 없으면 현재 조건을 기준으로 정보 미확인 포함, 마감 포함, 추가모집·관심 저장·관심 조건·모집 상태·지역·면적·금액 순서의 완화 선택지를 최대 3개 제공한다. 각 선택지는 해당 조건만 바꾸고 즉시 같은 URL 기반 검색을 다시 실행한다.
- 결과 화면의 링크 복사는 현재 URL을 사용하며, 제목 아래에는 사람이 읽을 수 있는 검색 조건 요약을 표시한다. `관심 조건 일치`·`관심 저장만`은 브라우저별 저장값을 사용하므로 공유받는 환경에서 결과가 달라질 수 있음을 안내한다.
- `공고 더 보기`는 현재 누적 표시 수와 남은 건수를 보여준다. 페이지 요청 중에는 기존 목록을 유지하고 로딩 상태를 안내하며, 응답의 `page`가 현재 요청 페이지와 같을 때만 목록에 추가해 이전 응답 중복을 막는다. 추가 요청 실패 시 기존 목록은 유지하고 재시도를 제공한다.
- 관심 저장은 브라우저별 목록으로 유지한다. 저장된 카드는 `관심 저장됨` 상태와 `aria-pressed`를 표시하고, 상단 `관심 저장` 메뉴는 `/announcements?savedOnly=true` 검색 화면으로 연결한다.
- `관심 저장만` 검색에서 브라우저 저장 목록 자체가 비어 있으면 조건 완화 제안 대신 저장 방법과 `공고 찾기로 이동` 동작을 제공한다. 저장 목록은 있지만 다른 조건 때문에 결과가 없으면 일반 조건 완화 안내를 사용한다.
- 관심 저장 ID 목록의 배열 순서는 사용자가 정한 저장 순서다. `관심 저장만` 화면은 `sort=SAVED`로 서버에 전달하며, 서버는 저장 ID의 순서대로 결과를 반환한다. 카드의 위·아래 동작은 순서를 변경한 뒤 첫 페이지를 다시 불러온다.
- 관심 저장 공고별 메모는 브라우저 저장소의 `공고 ID → 최대 300자 텍스트` 구조로 관리한다. 저장 목록 화면에서만 추가·수정·삭제하며, 공고를 관심 저장 해제하면 관련 메모도 함께 제거한다. 메모는 개인 브라우저 정보이므로 링크 공유·서버 데이터에는 포함하지 않는다.
- 관심 저장 공고별 확인 알림 시점은 브라우저 저장소의 `공고 ID → local datetime` 구조로 관리한다. 저장 목록 화면에서 예정 또는 지남 상태를 표시하고 수정·삭제할 수 있다. 백그라운드 푸시·브라우저 알림 권한은 이번 범위에 포함하지 않으며, 알림 시점은 화면을 열었을 때 확인한다.
- `확인 시점 지난 공고만`은 관심 저장 목록에서만 사용할 수 있다. 현재 시각보다 이전인 알림 시점을 가진 저장 ID만 서버의 `savedId` 조건으로 전달해 페이지가 나뉘어도 결과가 누락되지 않게 한다. 해당 공고가 없을 때는 알림 필터 해제 동작을 안내한다.
- 관심 저장 공고는 접수 마감일이 오늘 또는 3일 이내인 경우에만 `오늘 마감` 또는 `마감 D-n` 상태를 표시한다. 날짜만 있는 마감일은 해당 지역 날짜의 23:59:59까지 유효한 것으로 계산하며, 지난 날짜·미기재 날짜에는 상태를 표시하지 않는다.
- `마감 임박 공고만`은 오늘부터 3일 이내의 접수 마감일을 서버 SQL에서 검색한다. 관심 저장 여부와 무관하게 사용할 수 있으며, 결과가 없을 때는 해당 필터만 해제하는 안내를 제공한다.

## API 변환

| UI 조건 | API 파라미터 |
| --- | --- |
| 지역 계층 | 가장 상세한 지역을 `region` |
| 전용면적 | `areaMin`, `areaMax` |
| 출처 | `source` |
| 마감 포함 | `includeClosed` |
| 정보 미확인 포함 | `includeUnknown` |
| 관심 조건 일치 | `interestOnly`, `interestRegion`, `interestDepositMaxWon`, `interestRentMaxWon`, `interestAreaMin`, `interestAreaMax`, `interestIncludeUnknown` |
| 관심 저장만 | `savedOnly`, 반복 `savedId` |
| 추가모집만 | `supplementalOnly` |
| 정렬 | `sort` |

## 완료 기준

- 모든 필터가 검색 버튼을 누른 뒤에만 결과에 적용된다.
- URL 새로고침·뒤로 가기에서 적용 조건이 복원된다.
- 초기화는 조건·페이지·누적 목록을 함께 초기화한다.
- 서버 응답의 `hasNext`와 `totalCount`를 그대로 사용한다.
